# 컨텍스트 검색 정책 (Context Search Policy)

> 히스토리·이슈·To-Do·의사결정·변경이력·회의록 등 시간순 누적 문서를 검색할 때 비서가 따르는 기본 윈도우와 확장 규칙

---

## 1. 기본 검색 윈도우

- **최근 14일 (2주)** — 오늘 기준 D-13 ~ D 범위 (양 끝 포함)
- 월 경계가 걸치면 **현재 월 파일 + 직전 월 파일** 2개를 함께 본다 (예: 5월 18일 기준 → `202605*.md` + `202604*.md`)
- 그 외 더 오래된 월 파일은 **기본 검색에서 제외**

## 2. 적용 대상 파일

윈도우 규칙은 아래 시간순 누적 문서에 모두 적용:

| 카테고리 | 경로 패턴 |
|---|---|
| 글로벌 히스토리 | `platform/history/YYYYMM*.md` |
| 프로젝트 히스토리 | `projects/*/_manage/history/YYYYMM*.md` |
| 이슈 | `projects/*/_manage/issues.md` (날짜 항목 단위) |
| To-Do | `projects/*/_manage/todo.md` (날짜 항목 단위) |
| 의사결정 | `projects/*/_manage/decisions.md` (날짜 항목 단위) |
| 변경이력 | `projects/*/_manage/changelog.md` (날짜 항목 단위) |
| 회의록 | `projects/*/_manage/meetings/YYYY-MM-DD*.md` |

단일 파일(이슈·To-Do·의사결정·변경이력)은 **파일 전체를 읽되 윈도우 밖 항목은 매칭 결과에서 제외**한다.

## 3. 윈도우 밖(과거) 검색 트리거

### 3-1. Jacey 명시 요청 시 (1순위)

다음 표현 감지 시 즉시 전체 범위로 확장:
- "전체 히스토리에서", "처음부터", "작년부터", "초창기", "지금까지 모든"
- 절대 날짜·월 지정: "2026-03부터", "3월 이후", "지난 분기"
- 프로젝트 코드·이슈 ID 등 **고유 식별자**가 포함된 경우 (예: `P2605081`, `O001`, `DEV_D001`)

### 3-2. 비서 자동 확장 (2순위)

기본 윈도우 검색 결과가 **0건**이고 Jacey 질문이 과거 정보를 필요로 할 가능성이 높을 때:
- 1차 확장: 최근 **60일** (직전 2개월)
- 2차 확장: 최근 **6개월**
- 3차 확장: 전체

확장 시에는 반드시 답변에 **"기본 2주 범위에는 결과가 없어 N개월로 확장했습니다"** 같은 문구로 사실을 명시한다 (응답 규칙 3 — 사실 기반).

## 4. 윈도우 미적용 — 전체 검색이 기본인 문서

아래 문서는 시간순 누적이 아니거나 "현재 상태"가 의미를 가지므로 **항상 전체**를 본다:

- `CLAUDE.md` (모든 레이어)
- `PROJECTS_GLOBAL.md`
- `platform/TRIGGERS.md`
- `platform/guides/**`, `platform/project/**`, `platform/setup/**`
- `projects/*/CLAUDE.md`
- 산출물(HTML·기획서·설계서 등 — 시간순 누적이 아닌 버전 관리 대상)

> 비서 판단으로 "이 문서는 전체 검색이 효율적"이라고 보이는 항목이 더 있으면 Jacey에게 제안 후 본 정책에 추가한다.

## 5. 적용 우선순위

1. Jacey의 **명시 요청**이 있으면 그것이 최우선 (윈도우 무시)
2. 명시 요청 없으면 **기본 2주 윈도우** 적용
3. 결과 0건 + 과거 정보 필요성이 명확하면 자동 확장 (3-2)
4. 자동 확장 사실은 답변에 항상 명시
