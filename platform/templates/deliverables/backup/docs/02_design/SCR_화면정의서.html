SCR화면정의서 — Screen Specification

화면 단위로 청크된다. 1 화면 = 1 청크(screen:###). 화면 내 필드 표·액션·검증은 같은 청크에 포함. 화면이 매우 크면 screen:###:section 으로 분할 가능.
작성 점검 체크리스트필수 9
  • 메타바 6개
  • 분류 태그 3개
  • 화면 목록 (전체 카탈로그)
  • 각 화면: 목적·진입경로·필드·액션·상태/검증
  • 각 화면 → 상위 REQ Trace
  • 각 화면 → 하향 FUNC Trace
  • 화면 ≥ 1건
  • 액션 ≥ 1건

1.개요

본 문서는 전자결재 시스템의 화면별 레이아웃·필드·액션·상태를 정의한다. 화면 ID(EM2026-SCR-###)는 상위 REQ-F##와 하향 FUNC-### 에 양방향 추적된다.

2.화면 목록

ID화면명설명플랫폼
EM2026-SCR-001기안문 작성양식 선택·본문 작성·임시저장Web
EM2026-SCR-002결재선 지정결재자/합의자/참조자 순서 지정Web
EM2026-SCR-003결재 처리승인·반려·보류 + 의견 입력Web
EM2026-SCR-010모바일 결재앱 내 결재 처리Mobile

3.화면 상세

SCR-001 · 기안문 작성
목적사용자가 결재 양식을 선택하고 본문을 작성한다
진입 경로대시보드 → "새 기안" 버튼
권한전 직원 (ROLE-001 Drafter)
레이아웃좌: 양식 선택 / 중: 본문 에디터 / 우: 첨부·미리보기

필드

필드타입필수검증 / 비고
제목text(120)Y공백 불가
양식selectY활성 양식만
본문richtextY최대 50KB
첨부file[]N각 ≤20MB · 최대 10개 (REQ-F04)
임시저장auto—30초 간격, localStorage

액션

  • 임시저장 — 검증 없이 저장. PUT /drafts/{id}
  • 다음 (결재선 지정) — 필수 필드 검증 통과 시 SCR-002로 이동
  • 취소 — 변경 사항 폐기 확인 후 대시보드 복귀

상태 / 빈상태 / 에러

  • 로딩 — 양식 목록 fetch 중 스켈레톤 노출
  • 빈상태 — 양식 없음 → 관리자 문의 안내
  • 에러 — 첨부 용량 초과 시 인라인 에러 + 행 강조
SCR-002 · 결재선 지정
목적결재자/합의자/참조자 순서 지정
진입 경로SCR-001에서 "다음" 클릭
권한기안자 본인 (ROLE-001)

필드

필드타입필수검증
결재자user[]Y≥ 1명, 본인 제외
합의자user[]N중복 불가
참조자user[]N—

액션

  • 상신 — POST /approvals
  • 이전 — SCR-001로 복귀, 입력값 유지
SCR-003 · 결재 처리

결재자가 문서 내용 검토 후 승인/반려/보류 처리.

필드

필드타입필수검증
처리 결과radioY승인/반려/보류 중 1
의견text(500)COND반려 시 필수

액션

  • 처리 확정 — POST /approvals/{id}/decisions
SCR-010 · 모바일 결재

SCR-003의 모바일 변형. 첨부는 미리보기로 제한, 지문/PIN 인증 후 처리.

액션

  • 승인 (지문) — Biometric 인증 후 처리
  • 반려 (의견 필수)

4.공통 컴포넌트

  • UserPicker — 조직도 트리 + 검색. 그룹 단위 선택 지원.
  • FilePicker — 드래그&드롭. 용량 검증 인라인.
  • RichTextEditor — TipTap 기반. 표·이미지·붙여넣기 정화.
