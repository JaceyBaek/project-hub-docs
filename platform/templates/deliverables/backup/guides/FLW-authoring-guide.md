## 0. 작성 절차 (반드시 이 순서)

1. 템플릿 복사 → `projects/<프로젝트>/docs/02_design/FLW_<프로젝트명>_프로세스흐름도_<YYYYMMDD>.html`
2. **`<meta>` 단일 소스 갱신** — project-id / doc-id / doc-owner / doc-epic / doc-tags / embedding-hints / primary-entities
3. **head `<title>`** — `FLW · {시스템명} 프로세스흐름도`
4. **액터(§2) ≥ 2명** 정의 — 역할/책임 명시
5. **흐름 목록(§3)** 작성 — ID·중요도·상위 REQ trace 모두 채움
6. **표준 흐름 상세(§4)** — 각 흐름에 트리거/입력/출력/SLA + 경로 + 분기
7. **예외 흐름(§5)** ≥ 1건 — 발생/처리/제약 3요소
8. **AI 메타데이터(§6)** 갱신
9. **검증표(§7)** 자동 계산 — 모든 행 PASS 확인
10. 자가 점검(§5) 후 상태를 `Review`로

## 1. 필드 마커 의미

| 마커 | 의미 | 처리 |
|---|---|---|
| `REQ` | Required — 필수 | 누락 시 검증표 FAIL |
| `OPT` | Optional — 선택 | 해당 없으면 섹션 제거 가능 |
| `COND` | Conditional — 조건부 | 조건 충족 시에만 필수 |

## 2. ID 명명 규칙

- 흐름: `{PROJECT}-FLW-###` (예: `EM2026-FLW-001`)
- 노드: `{PROJECT}-FLW-###-S##` (S = Step, zero-pad 2자리)
- 분기: `{PROJECT}-FLW-###-B##` (B = Branch)
- 예외: `{PROJECT}-FLW-###-E##` (E = Exception)
- 흐름 번호는 3자리 zero-pad. 한 번 부여된 ID는 변경/재사용 금지.

---

## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 대상 시스템 흐름의 범위와 가독 규칙 1~2문단.
- 모든 흐름은 상위 REQ와 하향 SCR/FUNC에 양방향 추적된다는 점 명시.

### §2 액터 정의 (REQ)
- 최소 2명. 역할 + 책임 범위 명확화.
- 시스템 외부 트리거 주체만 (내부 모듈은 액터 아님).
- 액터 ID 패턴: `actor:<role>` (data-chunk 속성).

### §3 흐름 목록 (REQ)
- 전체 흐름 카탈로그. 본 문서가 다루는 흐름은 모두 여기에.
- 칼럼: ID / 흐름명 / 설명 / 중요도(High/Medium/Low) / 상위 REQ.
- `data-trace-up` 속성으로 상위 REQ ID 콤마구분 명시.

### §4 표준 흐름 상세 (REQ)
- 각 흐름은 **트리거 / 입력 / 출력 / SLA** 4요소 + **표준 경로 + 분기** 필수.
- 경로 단계는 `<ol class="step-list">`, 각 `<li>`에 `data-chunk="node:..."`.
- 단계마다 관련 SCR / FUNC ID 인라인 표기.
- `data-trace-down` 으로 하향 SCR/FUNC ID 콤마구분 명시.

### §5 예외 / 보상 흐름 (REQ)
- ≥ 1건. 각 예외는 **발생 / 처리 / 알림(또는 제약)** 3블록.
- `data-chunk="exception:..."`, `data-trace-up`으로 상위 흐름 ID 명시.

### §6 AI 학습 메타데이터 (REQ)
- `<meta>` 값과 일치해야 함. 불일치 시 검증표 FAIL.
- `primary_entities`: 도메인 핵심 명사 5~10개.
- `embedding_hints`: 1~2문장 요약 (키워드 나열 금지).

### §7 검증표 (REQ, 자동)
- `assets/doc-validator.js`가 DOM 검사 후 자동 채움.
- 모든 행 PASS 전엔 상태 `Approved` 금지.

---

## 4. Trace 작성 원칙

- **양방향 필수**:
  - `data-trace-up` — 상위 REQ ID (콤마구분)
  - `data-trace-down` — 하향 SCR/FUNC ID (콤마구분)
- 흐름 단위 + 분기/예외 단위 모두 trace.
- ID는 반드시 프로젝트 prefix 포함: `EM2026-REQ-F01` (X: `REQ-F01`).
- Trace 누락은 검증표 FAIL.

## 6. 사용자에게 질문해야 할 시그널

다음 정보가 없으면 추측 금지, 사용자에 질문:

- 시스템명 / 프로젝트 코드 / Epic 코드 / 담당자
- 도메인 (전자결재/HR/회계 등)
- 대상 흐름 범위 (어떤 업무 프로세스를 다루는지)
- 액터 그룹 (실 사용자 역할)
- SLA 기준 (응답시간, 알림 도착시간 등)
- 예외 케이스 (장애·부재·회수·취소 등 도메인 특수 상황)
- 상위 REQ가 이미 작성되었는지 (있다면 trace 즉시 연결)

질문은 5~7개 묶음으로 한 번에.

## 8. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| 내부 모듈(API, DB)을 액터로 표기 | 액터는 외부 트리거 주체만 |
| 표준 경로에 예외 케이스 포함 | §5 예외로 분리 |
| 분기를 `if-else` 코드 수준 디테일로 | 비즈니스 결정 분기만 (S-단계 변경 유발하는 것) |
| Trace를 흐름에만 달고 분기/예외 누락 | 모든 노드 trace 필수 |
| `embedding_hints`에 태그 나열 | 1~2문장 자연어 요약 |
