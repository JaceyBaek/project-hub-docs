§1 개요

목적

본 문서는 근태관리 시스템(Employee Attendance Management) 구축을 위한 요구사항을 정의합니다. 직원의 근무시간 자동화 기록과 결재 워크플로우 디지털화를 통해 근로기준법 준수 및 HR 업무 효율화를 목표로 합니다.

범위

  • 출퇴근 관리: QR코드·모바일 앱 기반 출퇴근 기록
  • 결재 워크플로우: 반차·연차·외출 전자 결재 신청 및 팀장 승인
  • 근태 통계: 일/주/월 단위 근태 현황 집계 및 시각화
  • 급여 연동: 월말 급여 시스템으로 근태 데이터 자동 전송

성공 기준

  • QR 출퇴근 기록률 100% (수동 기록 0%)
  • 결재 처리 평균 시간 50% 단축 (현행 2일 → 목표 1일 이내)
  • HR 급여 입력 수동 오류율 0% 달성
  • 출퇴근 기록 API 응답시간 2초 이내

§2 용어 정의

용어정의
출근직원이 업무 시작 시 시스템에 기록하는 행위. QR코드 스캔 또는 앱 버튼 클릭으로 수행.
퇴근직원이 업무 종료 시 시스템에 기록하는 행위. 자동 인식 또는 수동 기록.
근태근무 태도의 줄임말. 출퇴근 시간, 지각·조퇴·결근 여부를 포함한 종합 근무 상태.
결재반차·연차·외출 등 부재 사유를 팀장이 승인하는 전자 결재 프로세스.
반차오전 또는 오후 4시간 단위로 사용하는 연차 휴가의 절반.
연차근로기준법에 따라 부여되는 유급 휴가. 1일 단위 사용.
RBACRole-Based Access Control. 역할(직원·팀장·HR·관리자) 기반 접근 제어.

§6 비기능 요구사항 (NFR)

성능

  • 출퇴근 기록 API 응답시간: 2초 이내 (P95 기준)
  • 근태 통계 조회 응답시간: 3초 이내 (Redis 캐시 활용, 15분 TTL)
  • 동시 접속 사용자: 최소 200명 처리 가능

가용성

  • 서비스 가용성: 평일 06:00~22:00 기준 99.5% 이상
  • 계획 점검 시간: 매주 일요일 00:00~04:00 (공지 후 진행)
  • 장애 복구 목표(RTO): 2시간 이내

보안

  • 개인정보보호법 준수 (이름·전화번호·출퇴근 시각 암호화 저장)
  • JWT Bearer 토큰 인증, 만료시간 8시간
  • RBAC 기반 API 접근 제어 (역할별 엔드포인트 권한 분리)
  • 출퇴근 기록 감사 로그 5년 보존 (근로기준법)

호환성

  • 데스크톱: Chrome 최신 버전, Edge 최신 버전
  • 모바일: iOS Safari 16+, Android Chrome 최신 버전
  • 화면 해상도: 1280×720 이상 (데스크톱), 375×667 이상 (모바일)
