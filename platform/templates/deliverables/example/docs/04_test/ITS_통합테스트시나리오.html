§1 테스트 범위 및 환경 개요

통합 테스트는 단위 테스트에서 격리된 외부 컴포넌트(PostgreSQL, Redis)를 실제 컨테이너로 구동하여 전체 데이터 흐름을 검증합니다.

항목설정
테스트 범위FastAPI ↔ PostgreSQL 16 ↔ Redis 7.2 실제 컨테이너 연동
컨테이너 구동docker-compose -f docker-compose.test.yml up -d
테스트 프레임워크pytest 7.x + httpx (비동기 HTTP 클라이언트)
테스트 데이터fixtures/integration_data.json에서 로드
테스트 실행 명령pytest tests/integration/ -v --timeout=30
CI 실행 조건main 브랜치 PR merge 전 필수 통과

§3 시나리오 상세

ITS-S01 출퇴근 기록 → 통계 갱신 E2E

항목내용
목적출근 기록 → Redis 캐시 무효화 → 퇴근 기록 → 통계 조회까지 전체 흐름 검증
선행 조건직원 EMP001 존재, 당일(2026-05-26) 출퇴근 기록 없음, Redis 캐시 초기화 상태
판정 기준각 API 응답 2초 이내, work_minutes = 540, Redis 캐시 갱신 확인

실행 스텝

1
출근 기록 — POST /api/v1/attendance/clock-in
Body: {"employee_id": "EMP001-UUID", "timestamp": "2026-05-26T09:00:00+09:00", "location": {"lat": 37.5, "lng": 127.0}}
기대 응답: 201, status: "normal"
2
Redis 캐시 무효화 확인
redis-cli GET stats:EMP001-UUID:2026-05 → nil (캐시 삭제됨)
3
퇴근 기록 — POST /api/v1/attendance/clock-out
Body: {"employee_id": "EMP001-UUID", "timestamp": "2026-05-26T18:00:00+09:00"}
기대 응답: 200, work_minutes: 540
4
통계 조회 — GET /api/v1/attendance/EMP001-UUID/stats?from=2026-05-26&to=2026-05-26
기대 응답: 200, present_days: 1, total_work_minutes: 540
5
Redis 캐시 재생성 확인
redis-cli EXISTS stats:EMP001-UUID:2026-05 → 1 (캐시 갱신됨)

ITS-S02 결재 신청 → 팀장 승인 → 상태 반영 E2E

항목내용
목적직원 휴가 신청 → 팀장 승인 → 상태 전이 → 이메일 알림 발송 전체 흐름 검증
선행 조건직원 EMP001 (ROLE-01), 팀장 MGR001 (ROLE-02, 동일 팀) 존재. 이메일 서비스 mock 설정 완료
판정 기준상태 전이 정확 (pending → approved), 이메일 mock 호출 1회, 총 소요 3초 이내

실행 스텝

1
EMP001 로그인 — POST /api/v1/auth/login
Body: {"emp_no": "EMP001", "password": "..."}
기대 응답: 200, access_token 발급 → 이후 요청에 Authorization: Bearer <token> 사용
2
휴가 신청 — POST /api/v1/leave/request
Body: {"leave_type": "annual", "start_at": "2026-06-02T09:00:00+09:00", "end_at": "2026-06-02T18:00:00+09:00", "reason": "통합 테스트용 연차"}
기대 응답: 201, request_id 반환, status: "pending"
3
DB 상태 직접 확인
PostgreSQL: SELECT status FROM leave_requests WHERE id = '{request_id}'; → pending
4
MGR001 로그인 — POST /api/v1/auth/login
MGR001 JWT 발급 → 이후 요청에 사용
5
휴가 승인 — PUT /api/v1/leave/request/{request_id}/approve
Body: {"approved": true, "comment": "승인합니다."}
기대 응답: 200, status: "approved"
6
DB 상태 재확인
PostgreSQL: SELECT status, approved_by FROM leave_requests WHERE id = '{request_id}'; → approved, approved_by = MGR001-UUID
7
이메일 알림 발송 확인
email_service mock 호출 횟수 검증 → send_email.call_count == 1, 수신자 = EMP001 이메일

§4 테스트 환경 설정

docker-compose.test.yml 구성

version: '3.9'
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: attendance_test
      POSTGRES_USER: test_user
      POSTGRES_PASSWORD: test_pass
    ports:
      - "5433:5432"  # 로컬 충돌 방지

  redis:
    image: redis:7.2-alpine
    ports:
      - "6380:6379"  # 로컬 충돌 방지

  app:
    build: .
    environment:
      APP_ENV: test
      DB_HOST: db
      DB_PORT: 5432
      DB_NAME: attendance_test
      DB_USER: test_user
      REDIS_URL: redis://redis:6379/0
    depends_on:
      - db
      - redis
    ports:
      - "8001:8000"

테스트 실행 순서

# 1. 컨테이너 시작
docker-compose -f docker-compose.test.yml up -d

# 2. DB 마이그레이션 (테스트 DB)
alembic -x env=test upgrade head

# 3. 테스트 데이터 로드
python scripts/load_fixtures.py --env test

# 4. 통합 테스트 실행
pytest tests/integration/ -v --timeout=30

# 5. 컨테이너 정리
docker-compose -f docker-compose.test.yml down -v

§5 테스트 데이터

테스트 데이터는 fixtures/integration_data.json에서 로드합니다. 아래는 핵심 fixture 구조입니다.

{
  "employees": [
    {
      "emp_no": "EMP001",
      "name": "테스트직원",
      "email": "emp001@test.internal",
      "role": "EMPLOYEE",
      "team_id": "TEAM001"
    },
    {
      "emp_no": "MGR001",
      "name": "테스트팀장",
      "email": "mgr001@test.internal",
      "role": "MANAGER",
      "team_id": "TEAM001"
    }
  ],
  "teams": [
    {
      "team_id": "TEAM001",
      "name": "개발1팀",
      "manager_emp_no": "MGR001"
    }
  ]
}
⚠️
테스트 데이터는 테스트 DB 전용입니다. 스테이징/운영 DB에 절대 로드하지 마세요. 패스워드는 bcrypt 해시로 저장해야 합니다 — 평문 저장 금지.
