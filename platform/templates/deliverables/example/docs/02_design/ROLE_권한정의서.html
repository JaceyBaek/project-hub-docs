§1 역할 목록

ℹ️ 모든 역할은 JWT 토큰의 role 클레임으로 식별됩니다. FastAPI 미들웨어에서 RBAC 검사가 수행됩니다.
역할 ID역할명 (코드)설명초기 할당 기준
ROLE-01 직원 (employee) 일반 직원. 자신의 출퇴근 기록 및 결재 신청 가능. 신규 입사 시 기본 할당
ROLE-02 팀장 (manager) 팀원 근태 조회 및 결재 승인/반려 권한 보유. 부서 팀장 직책 부여 시 관리자가 수동 할당
ROLE-03 HR담당자 (hr) 전체 직원 근태 조회, 급여 연동 실행, 보고서 추출 가능. HR팀 부서 배속 시 관리자가 수동 할당
ROLE-04 시스템관리자 (admin) 사용자 계정 관리, 시스템 설정, 감사 로그 조회 가능. IT팀 시스템관리자 직책 부여 시 할당

§2 역할별 권한 상세

ROLE-01 직원 (employee)
  • 자신의 출퇴근 기록 조회·생성·수정 (당일 기록만 수정 가능)
  • 자신의 근태 통계 조회 (일/주/월)
  • 결재 신청 생성 및 본인 신청 내역 조회
  • 본인 신청 건 취소 (pending 상태일 때만)
  • 타인의 출퇴근 기록·통계 조회 불가
ROLE-02 팀장 (manager)
  • 직원 권한 전부 포함
  • 소속 팀원의 출퇴근 기록 조회 (읽기 전용)
  • 소속 팀원의 근태 통계 조회
  • 팀원의 결재 신청 승인 또는 반려 (반려 사유 필수)
  • 팀원 결재 내역 조회
  • 다른 팀 데이터 접근 불가
ROLE-03 HR담당자 (hr)
  • 전체 직원 출퇴근 기록 조회 (부서·개인 무관)
  • 전체 직원 근태 통계 조회 및 엑셀/CSV 내보내기
  • 월말 급여 연동 실행 (export_payroll_data)
  • 보고서 생성 및 다운로드
  • 결재 신청/승인 불가 (조회만 가능)
  • 사용자 계정 관리 불가
ROLE-04 시스템관리자 (admin)
  • 사용자 계정 생성·조회·수정·비활성화 (CRUD)
  • 역할 할당 및 변경
  • 시스템 설정 관리 (근무 시간 기준, 지각 판단 시각 등)
  • 감사 로그 전체 조회 (출퇴근 이벤트 포함)
  • 모든 데이터 읽기 전용 조회
  • 급여 연동 실행 불가 (HR 전용)

§4 역할 전환 조건

전환 시나리오이전 역할이후 역할처리 방법담당자
팀장으로 발령 employee manager 관리자 화면에서 역할 수동 변경. JWT 토큰 갱신 필요(재로그인). 시스템관리자
팀장직 해임 · 부서 이동 manager employee 관리자 화면에서 역할 자동 강등. 기존 팀원 연결 해제. 시스템관리자
HR팀 이동 기존 역할 hr HR팀 부서 코드 배속 확인 후 수동 할당. 시스템관리자
HR팀 이탈 hr employee 부서 이동 처리 시 역할 자동 회수. 시스템관리자
퇴직 처리 모든 역할 비활성 (is_active=false) 계정 비활성화. 데이터 보존(5년). 즉시 로그인 차단. 시스템관리자
⚠️ 역할 변경 후 기존 JWT 토큰은 만료 시까지 유효합니다. 즉시 권한 회수가 필요한 경우(퇴직, 보안 사고) 관리자가 해당 사용자의 모든 토큰을 즉시 무효화해야 합니다. 토큰 블랙리스트는 Redis에 관리됩니다.

✅ 검증 체크리스트

역할 4종(직원·팀장·HR·관리자) 모두 정의 완료
권한 매트릭스가 FUNC 기능정의서의 모든 기능을 커버하는가
역할 전환 시나리오 5종 정의 완료
JWT 토큰 블랙리스트 정책(즉시 무효화)이 정의되었는가
각 역할의 데이터 조회 범위(자신/팀/전체)가 명확한가
SEC 보안설계서와 RBAC 정책 일치 여부 확인 (SEC-01 작성 후)
