§1 ERD (Entity Relationship Diagram)

⚠️ PII 표시 컬럼은 개인정보보호법 대상 개인식별정보입니다. 암호화 저장 및 접근 제어 적용 필수.
📊
ERD (Mermaid erDiagram)
erDiagram Department { UUID id PK VARCHAR(20) code UK VARCHAR(100) name UUID manager_id FK UUID parent_id FK } Employee { UUID id PK VARCHAR(10) emp_no UK VARCHAR(50) name "PII" UUID dept_id FK ENUM role VARCHAR(100) email "PII" VARCHAR(20) phone "PII" TIMESTAMP created_at BOOLEAN is_active } AttendanceRecord { UUID id PK UUID employee_id FK TIMESTAMP clock_in_at "PII" TIMESTAMP clock_out_at "PII" POINT location_in "PII" INT work_minutes ENUM status BOOLEAN is_deleted TIMESTAMP created_at } LeaveRequest { UUID id PK UUID employee_id FK ENUM leave_type TIMESTAMP start_at TIMESTAMP end_at TEXT reason ENUM status UUID approver_id FK TIMESTAMP approved_at TIMESTAMP created_at } Department ||--o{ Employee : "소속" Employee ||--o| Employee : "팀장(self-ref)" Employee ||--o{ AttendanceRecord : "출퇴근 기록" Employee ||--o{ LeaveRequest : "결재 신청" Employee ||--o{ LeaveRequest : "결재 승인(approver)" Department ||--o| Department : "상위 부서(self-ref)"

§2 엔티티 상세 정의

2.1 Employee (직원)

컬럼명타입제약조건설명
idUUIDPK, NOT NULL, DEFAULT gen_random_uuid()직원 고유 식별자
emp_noVARCHAR(10)NOT NULL, UNIQUE사번 (예: EMP00001)
namePIIVARCHAR(50)NOT NULL성명. 암호화 저장 대상.
dept_idUUIDFK → Department.id, NOT NULL소속 부서
roleENUMNOT NULL, DEFAULT 'employee'employee / manager / hr / admin
emailPIIVARCHAR(100)NOT NULL, UNIQUE이메일. 알림 발송에 사용. 암호화 저장.
phonePIIVARCHAR(20)NULL 허용휴대전화번호. 암호화 저장.
manager_idUUIDFK → Employee.id, NULL 허용직속 팀장. Self-reference.
created_atTIMESTAMP WITH TIME ZONENOT NULL, DEFAULT now()계정 생성 일시
is_activeBOOLEANNOT NULL, DEFAULT truefalse = 퇴직 처리. 로그인 차단.

2.2 AttendanceRecord (출퇴근 기록)

컬럼명타입제약조건설명
idUUIDPK, NOT NULL, DEFAULT gen_random_uuid()기록 고유 식별자
employee_idUUIDFK → Employee.id, NOT NULL직원 참조
clock_in_atPIITIMESTAMP WITH TIME ZONENOT NULL출근 시각. KST 저장. 개인식별 정보로 분류.
clock_out_atPIITIMESTAMP WITH TIME ZONENULL 허용퇴근 시각. 출근 후 미퇴근 시 NULL.
location_inPIIPOINT (PostGIS)NULL 허용출근 시 GPS 좌표. 위치정보 = PII.
work_minutesINTNULL 허용, CHECK ≥ 0총 근무 분 (퇴근 후 계산). 퇴근 전 NULL.
statusENUMNOT NULL, DEFAULT 'normal'normal / late / early_leave / absent
is_deletedBOOLEANNOT NULL, DEFAULT false논리 삭제 플래그. 물리 삭제 금지.
created_atTIMESTAMP WITH TIME ZONENOT NULL, DEFAULT now()레코드 생성 일시

2.3 LeaveRequest (결재 신청)

컬럼명타입제약조건설명
idUUIDPK, NOT NULL, DEFAULT gen_random_uuid()결재 신청 고유 ID
employee_idUUIDFK → Employee.id, NOT NULL신청자 직원
leave_typeENUMNOT NULLannual (연차) / half_am / half_pm (반차) / out (외출)
start_atTIMESTAMP WITH TIME ZONENOT NULL부재 시작 일시
end_atTIMESTAMP WITH TIME ZONENOT NULL, CHECK > start_at부재 종료 일시
reasonTEXTNOT NULL, CHECK length ≥ 10신청 사유. 최소 10자.
statusENUMNOT NULL, DEFAULT 'pending'pending / approved / rejected / cancelled
approver_idUUIDFK → Employee.id, NULL 허용승인자 (pending 시 NULL)
approved_atTIMESTAMP WITH TIME ZONENULL 허용승인/반려 처리 일시
created_atTIMESTAMP WITH TIME ZONENOT NULL, DEFAULT now()신청 일시

2.4 Department (부서)

컬럼명타입제약조건설명
idUUIDPK, NOT NULL, DEFAULT gen_random_uuid()부서 고유 ID
codeVARCHAR(20)NOT NULL, UNIQUE부서 코드 (예: HR, IT, SALES)
nameVARCHAR(100)NOT NULL부서명 (예: 인사팀, IT팀)
manager_idUUIDFK → Employee.id, NULL 허용부서 팀장. Self-reference with Employee.
parent_idUUIDFK → Department.id, NULL 허용상위 부서 (NULL = 최상위 부서)

§4 데이터 보존·삭제 정책

테이블보존 기간근거삭제 방식
attendance_record 5년 근로기준법 제42조 (임금대장 등 근로관계 서류 보존) 논리 삭제 (is_deleted=true). 물리 삭제 절대 금지.
leave_request 5년 근로기준법 제42조 동일 적용 논리 삭제. status=cancelled로 상태 전환.
employee 5년 (퇴직 후) 개인정보보호법 (업무 관련 보존 기간) 논리 삭제 (is_active=false). PII 컬럼 마스킹 처리.
department 무기한 조직 이력 보존 필요 비활성 플래그 처리 (is_active 추가 예정).
ℹ️ PII 컬럼(name·email·phone·clock_in_at·location_in) 만료 처리 절차: 퇴직 5년 후 해당 컬럼을 마스킹 값("***")으로 UPDATE. 레코드 자체는 통계 무결성 유지를 위해 물리 삭제하지 않습니다.

§5 마이그레이션 관리

Alembic 1.13을 사용합니다. 모든 마이그레이션 스크립트는 up(upgrade)과 down(downgrade)을 모두 작성해야 합니다.

초기 마이그레이션 (0001_initial)

"""0001_initial: 4개 테이블 초기 생성"""

def upgrade():
    op.create_table('department',
        sa.Column('id', UUID(), primary_key=True, server_default=text('gen_random_uuid()')),
        sa.Column('code', sa.VARCHAR(20), nullable=False, unique=True),
        sa.Column('name', sa.VARCHAR(100), nullable=False),
        sa.Column('manager_id', UUID(), sa.ForeignKey('employee.id'), nullable=True),
        sa.Column('parent_id', UUID(), sa.ForeignKey('department.id'), nullable=True),
    )
    op.create_table('employee', ...)
    op.create_table('attendance_record', ...)
    op.create_table('leave_request', ...)
    # 인덱스 생성
    op.create_index('idx_att_emp_date', 'attendance_record',
                    ['employee_id', 'clock_in_at'])

def downgrade():
    op.drop_table('leave_request')
    op.drop_table('attendance_record')
    op.drop_table('employee')
    op.drop_table('department')
⚠️ 마이그레이션 실행 전 반드시 백업을 수행해야 합니다. 운영 환경 적용은 점검 시간(일요일 00:00~04:00) 내에 진행합니다.
