§2 STRIDE 위협 모델

근태관리 시스템의 주요 데이터 흐름(직원 → Nginx → FastAPI → PostgreSQL/Redis)을 대상으로 STRIDE 분석을 수행했습니다.

위협 유형시나리오심각도대응 방안상태
Spoofing
신원 위조		 JWT 토큰 위조로 타인 계정 접근 High 서명 검증(현재 HS256, RS256 전환 예정). 토큰 발급 시 device fingerprint 포함 부분 완료
Tampering
데이터 변조		 출퇴근 기록 직접 DB 수정으로 근무시간 위변조 High 감사 로그 테이블 + DB 트리거(UPDATE/DELETE 시 audit 기록). 감사 로그는 읽기 전용 권한으로만 접근 설계 완료
Repudiation
행위 부인		 팀장이 결재 처리 후 "승인한 적 없다" 부인 Medium 감사 로그에 처리자 UUID + 타임스탬프 + IP 기록. 로그 위변조 방지(append-only) 설계 완료
Info Disclosure
정보 유출		 PII(이름, 출퇴근 시각) 비인가 접근 또는 로그 노출 High DB 컬럼 암호화(AES-256). 로그에 PII 마스킹. 에러 메시지에 민감정보 미포함 부분 완료
Denial of Service
서비스 거부		 대량 요청으로 출퇴근 API 서비스 마비 Medium Rate Limiting (출퇴근 5회/분). Nginx worker_connections 제한. 비정상 IP 자동 차단(fail2ban) 설계 완료
Elevation of Privilege
권한 상승		 직원 계정으로 HR 결재 권한(ROLE-03) 획득 시도 High RBAC 미들웨어에서 엔드포인트별 권한 강제 검증. 역할은 JWT claim에 포함, 서버에서 재검증 설계 완료

패스워드 정책

  • 해시 알고리즘: bcrypt, rounds=12
  • 최소 길이: 8자 이상, 대/소문자+숫자+특수문자 조합
  • 로그인 실패 5회 연속 시 계정 잠금 (30분 자동 해제 또는 관리자 해제)
  • 평문 패스워드 로그 기록 금지 (미들웨어 수준 필터링)

구현 예시 (FastAPI 미들웨어)

from fastapi import Security, HTTPException, status
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials

security = HTTPBearer()

async def require_role(required_roles: list[str]):
    def dependency(
        credentials: HTTPAuthorizationCredentials = Security(security)
    ):
        payload = verify_jwt(credentials.credentials)
        if payload.get("role") not in required_roles:
            raise HTTPException(
                status_code=status.HTTP_403_FORBIDDEN,
                detail={"error": {"code": "Forbidden", "message": "권한이 없습니다."}}
            )
        return payload
    return dependency

감사 로그 보호

  • 감사 로그 테이블은 append-only: UPDATE, DELETE 권한 없음

  • 로그 내 PII는 마스킹 처리 (예: 이름 → "김**")
