1.개요

시스템의 데이터 구조 목적, 주요 저장소(RDBMS/NoSQL/캐시 등), 테이블 수 요약.

본 문서는 [시스템명]의 데이터 모델을 정의한다. 모든 테이블 정의는 아키텍처(ARC)의 데이터 아키텍처 섹션과 정합해야 하며, 기능정의서(FUNC)의 처리 로직과 연계된다.

주요 저장소
PostgreSQL 16 (주 DB) / Redis (세션 캐시) / S3 (파일 스토어)
범위
테이블 수: 약 10개 / 주요 도메인: 결재, 사용자, 감사
명명 규칙
snake_case / 복수형 테이블명 / PK: id (BIGSERIAL) / 생성·수정일: created_at, updated_at

7.데이터 정책

보존 기간·마이그레이션·백업·복구 RPO/RTO 명시. 법적 보존 의무가 있으면 근거 법령.
보존 정책
drafts / approvals: 결재 완료 후 5년 보존 → soft-delete 후 archive. audit_events: S3 append-only, 5년 보존 후 Glacier 이관.
백업 / 복구
RDS 자동 스냅샷 1일 1회 (보존 30일). RPO ≤ 1시간 (Point-In-Time Recovery). RTO ≤ 4시간.
마이그레이션
스키마 변경은 Flyway 마이그레이션 스크립트로 관리. Breaking change(컬럼 삭제/타입 변경)는 2단계 배포 원칙.
