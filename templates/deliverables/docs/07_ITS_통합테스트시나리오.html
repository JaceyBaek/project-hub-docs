1.개요

UTC가 통과한 기능들을 E2E 흐름으로 연결해 시스템 통합을 검증한다. 본 문서는 시나리오 단위로 작성된다.

2.테스트 환경

환경QA-Stage (qa.example.intra)
데이터익명화된 운영 스냅샷 (D-1)
계정U1 (Drafter), U2 (Approver), U3 (Delegate), Admin
외부 연동HRMS Mock, SSO Stub, Mail Sandbox

3.시나리오

ITS-001 · 기안 → 1차 승인 → 최종 승인 → 종결
  • Pre U1 로그인, 양식 F-001 활성
  • 1) U1, "휴가신청" 임시저장 → 결재선(U2→Admin) 지정 → 상신
  • 2) U2 로그인, 승인 처리
  • 3) Admin 로그인, 최종 승인
  • Then 상태=COMPLETED, 감사로그 3건, U1에게 알림 메일 1건
ITS-002 · 반려 → 보완 → 재상신
  • Pre ITS-001 환경 + 신규 임시저장
  • 1) U1 상신, U2가 사유 "첨부 누락"으로 반려
  • 2) U1, 임시저장 박스에서 문서 열어 첨부 추가 후 재상신
  • Then 새 결재 사이클 시작, 이전 사이클은 회수 상태로 감사 기록
ITS-003 · 위임 결재
  • Pre U2가 U3에게 14일 위임 등록, 위임 제외 카테고리 = [기밀]
  • 1) U1, 일반 카테고리 문서 상신
  • 2) 결재 라우팅 → U3로 자동 전환
  • 3) U3 승인 처리
  • Then 감사로그에 원 결재자(U2)/대결자(U3) 동시 기록
ITS-004 · 위임 제외 카테고리
  • Pre ITS-003과 동일 위임 상태
  • 1) U1, [기밀] 카테고리 문서 상신
  • Then 위임 적용 안됨, 원 결재자 U2에게 전달

4.실패 시 롤백

  • 각 시나리오 종료 시 testfixture 초기화 스크립트 실행 (scripts/teardown.sh)
  • 운영 데이터 오염 방지: 모든 메일은 Mail Sandbox로 라우팅
  • 실패 시 결과 캡처/로그를 Test Report에 첨부
