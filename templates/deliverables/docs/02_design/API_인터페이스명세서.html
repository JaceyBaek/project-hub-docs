1.개요

Base URL / 프로토콜 / API 버전 전략 / 인터페이스 유형(REST·gRPC·MCP tool 등) 명시.

프로토콜 / 형식

2.인증 / 인가

인증 방식(JWT·OAuth2·API Key 등), 토큰 수명, 권한 범위 명시.
인증 방식Bearer JWT (OIDC — Azure AD 발급). Authorization: Bearer {token}
토큰 수명Access Token 1시간 / Refresh Token 8시간
권한 범위Scope: approval:read / approval:write / admin
미인증 처리401 Unauthorized (토큰 없음 / 만료) / 403 Forbidden (권한 부족)

5.엔드포인트 상세

각 엔드포인트별 요청 파라미터·헤더·바디 스키마와 응답 예시. 핵심 엔드포인트 우선 작성.
POST /v1/drafts — 기안문 생성
Request Body 
{"title": "string (required, max 200)",
 "body": "string (required, max 50KB)",
 "form_id": "integer (required)"}
Response 201 
{"data": {"id": 1001, "status": "DRAFT", "created_at": "2026-05-12T14:30:00+09:00"}}
오류400 (필수 필드 누락) / 422 (form_id 미존재)
POST /v1/approvals/{id}/process — 결재 처리
Path Paramid: approval 고유 ID (integer)
Request Body 
{"result": "APPROVED | REJECTED",
 "comment": "string (반려 시 필수, max 500)"}
Response 200 
{"data": {"approval_id": 5001, "result": "APPROVED", "processed_at": "…"}}
오류400 (result 누락) / 409 (이미 처리됨) / 403 (결재자 불일치)
