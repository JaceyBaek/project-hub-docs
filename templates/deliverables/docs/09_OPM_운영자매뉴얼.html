1.개요

운영자가 시스템을 일상 관리·장애 대응하는 데 필요한 절차를 정의한다. 모든 명령은 ops-shell bastion에서 실행한다.

2.배포 절차

  1. 1) 변경 PR 머지 후 GitHub Actions deploy-stage 실행
  2. 2) Stage 환경 회귀 테스트 통과 확인 (Allure 리포트)
  3. 3) Change Advisory Board 승인 (Jira CHG 티켓)
  4. 4) deploy-prod 워크플로 수동 트리거 — 카나리 10% → 50% → 100%
  5. 5) 카나리 단계마다 5xx error rate < 0.5% 확인
  6. 6) 배포 후 30분 모니터링, Slack #ops-deploy에 결과 게시

3.모니터링 지표

지표임계치알림
API p95 응답시간> 1000ms (5분)PagerDuty P2
5xx 에러율> 1% (5분)PagerDuty P1
RDS CPU> 80% (10분)Slack #ops-alert
Kafka consumer lag> 10000 msgSlack #ops-alert

4.Runbook

RB-001 · 5xx 에러율 급증
  1. 진단 Grafana "approval-5xx" 대시보드 확인 → 특정 endpoint/AZ 식별
  2. 1차 조치 트래픽 격리: 영향 AZ를 ALB에서 drain
  3. 2차 조치 직전 배포가 원인이면 deploy-prod --rollback
  4. 커뮤니케이션 #incident 채널에 5분 단위 상황 공유, 30분 초과 시 운영팀장 호출
RB-002 · DB 부하 급증
  1. 진단 RDS Performance Insights에서 Top SQL 확인
  2. 1차 조치 long-running query는 pg_terminate_backend
  3. 2차 조치 캐시 워밍, read replica 가중치 ↑
RB-003 · Kafka consumer lag
  1. 진단 Audit Service 메트릭 확인, consumer thread dump
  2. 1차 조치 consumer 인스턴스 스케일 아웃 (2→4)
  3. 2차 조치 특정 토픽 파티션 rebalance

5.백업 / 복구
