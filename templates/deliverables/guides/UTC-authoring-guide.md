## 2. ID 명명 규칙

- 케이스: `{PROJECT}-UTC-###` (3자리 zero-pad)
- 케이스 그룹(대상 FUNC 묶음): `{PROJECT}-UTC-G##`
- 픽스처: `{PROJECT}-FIX-##`

---

## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 테스트 프레임워크(Jest / JUnit / PyTest 등).
- 커버리지 목표 (라인 / 분기 / 함수).
- 상위 FUNC-### 양방향 추적 명시.

### §2 테스트 대상 (REQ)
- 칼럼: FUNC ID / 기능명 / 케이스 수 / 커버리지 %.
- 1 FUNC ≥ 1 UTC 원칙. 0개면 검증 FAIL.

### §3 케이스 상세 (REQ) — **가장 중요**
각 케이스 카드는 **Given–When–Then** 형식 필수:
- **기본 정보**: 케이스명 / 대상 FUNC / 분류(정상/예외/경계) / 우선순위(P0/P1/P2)
- **Given** — 사전 조건 / 입력 데이터 / Mock 상태
- **When** — 실행 동작 (한 문장)
- **Then** — 기대 결과 (관찰 가능한 검증 ≥ 1건)
- **Mock/Stub** — 외부 의존 처리 (있는 경우)

카드 속성:
- `data-chunk="testcase:{ID}"`
- `data-trace-up="FUNC-###"`
- `data-trace-down=""` (UTC는 종착점, down 없음)

**케이스 분포 원칙** (1 FUNC 기준):
- 정상 케이스 ≥ 1
- 예외 케이스 ≥ 1 (FUNC §예외와 1:1 권장)
- 경계 케이스 ≥ 1 (입력 min/max, 빈 값, 최대 길이)

### §4 공통 픽스처 (OPT)
- 2개 이상 케이스가 공유하는 테스트 데이터·Mock 셋업.

### §5 AI 메타데이터 (REQ)
- `primary_entities`에 대상 FUNC 키워드.

### §6 검증표 (REQ, 자동)
- 1 FUNC ≥ 1 UTC / 각 케이스 Given·When·Then 채움 / 예외 케이스 ≥ FUNC §예외 수 / Trace-up 전건.

---

## 4. Trace 작성 원칙

- **단방향(trace-up)**:
  - `data-trace-up` — FUNC-### (필수, 1건)
  - `data-trace-down` — 없음
- 한 케이스가 여러 FUNC를 검증하면 통합테스트(ITS)로 분리.
- 모든 ID에 프로젝트 prefix.

- [ ] `<meta>` 모두 채움

- [ ] FUNC §예외 ↔ UTC 예외 케이스 1:1 (수량 일치)
- [ ] 각 케이스 Given·When·Then 모두 채움
- [ ] 각 케이스 분류(정상/예외/경계) + 우선순위(P0~P2)

- [ ] 경계 케이스 ≥ 1건 (각 FUNC당)
- [ ] 모든 케이스 trace-up
- [ ] 커버리지 목표 명시
- [ ] 검증표 전 행 PASS

## 7. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| Given 누락 (When만 적음) | 사전 상태·입력·Mock 셋업 명시 |
| Then 이 "정상 동작" 같이 모호 | 관찰 가능한 검증 (반환값·상태·이벤트) |
| FUNC §예외와 UTC 예외 수 불일치 | 1:1 또는 그 이상 |
| 경계 케이스 누락 | min/max/빈값/최대길이 중 ≥ 1 |
| Mock 사용 사실 누락 | 외부 의존은 모두 Mock/Stub 명시 |
| 우선순위 누락 | P0(필수)/P1(중요)/P2(여유) 부여 |
| 1 케이스에 여러 FUNC 검증 | ITS(통합테스트)로 분리 |
| Trace-up 누락 | UTC는 반드시 FUNC-### 1건 이상 |
