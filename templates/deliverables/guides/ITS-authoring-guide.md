## 0. 작성 절차

1. 템플릿 복사 → `projects/<프로젝트>/docs/04_test/ITS_<프로젝트명>_통합테스트시나리오_<YYYYMMDD>.html`
2. `<meta>` 단일 소스 갱신 (project-id / doc-id / owner / tags / primary-entities)
3. `<title>` — `ITS · {시스템명} 통합테스트시나리오`
4. **테스트 대상(§2)** — 대상 FLW 목록과 시나리오 수
5. **시나리오 상세(§3)** — 카드 단위 1 시나리오 = 1 청크
6. **테스트 환경(§4)** — 환경/데이터/계정 (선택)
7. **AI 메타데이터(§5)** 갱신
8. **검증표(§6)** 자동 계산, 모든 행 PASS

## 2. ID 명명 규칙

- 시나리오: `{PROJECT}-ITS-###`
- 시나리오 스텝: `{PROJECT}-ITS-###-S##`
- 분기 시나리오: `{PROJECT}-ITS-###-B##`

---

## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 테스트 범위 / 환경 / 도구 (Cypress / Playwright / Postman / k6 등).
- 상위 FLW-### 양방향 추적 명시.

### §2 테스트 대상 (REQ)
- 칼럼: FLW ID / 프로세스명 / 시나리오 수 / 우선순위.
- 1 FLW ≥ 1 ITS 원칙. 0개면 검증 FAIL.

### §3 시나리오 상세 (REQ) — **가장 중요**
각 시나리오 카드 필수 요소:
- **기본 정보**: 시나리오명 / 대상 FLW / 액터 / 사전 조건 / 우선순위(P0/P1/P2)
- **시나리오 스텝** — 순서 있는 단계 ≥ 3
  - 칼럼: # / 액터 / 액션 / 화면(SCR) / 기대 결과
- **데이터 셋업** — 필요한 사전 데이터 (계정·마스터·트랜잭션)
- **검증 포인트** — 종료 시점 + 중간 체크포인트 ≥ 2
- **분기/예외** — 정상 외에 ≥ 1건 (반려·취소·타임아웃 등)

카드 속성:
- `data-chunk="scenario:{ID}"`
- `data-trace-up="FLW-###,SCR-###,FUNC-###,..."`
- `data-trace-down=""` (시나리오는 종착점)

### §4 테스트 환경 (OPT)
- 환경 매트릭스 (DEV / STG / PROD-like).
- 테스트 계정·권한.
- 시드 데이터 위치.

### §5 AI 메타데이터 (REQ)
- `primary_entities`에 핵심 프로세스 키워드.

### §6 검증표 (REQ, 자동)
- 1 FLW ≥ 1 ITS / 각 시나리오 스텝 ≥ 3 / 검증 포인트 ≥ 2 / 분기·예외 ≥ 1 / Trace-up 전건.

---

## 4. Trace 작성 원칙

- **단방향(trace-up)**:
  - `data-trace-up` — FLW-### (필수, 주 대상), SCR-###·FUNC-### (스텝에서 사용)
  - `data-trace-down` — 없음
- ITS는 여러 산출물을 가로지르는 종착점.
- 모든 ID에 프로젝트 prefix.

---

## 5. 자가 점검 체크리스트

- [ ] `<meta>` 모두 채움
- [ ] 모든 FLW에 ≥ 1개 ITS 매핑
- [ ] FLW §분기(B##) ↔ ITS 분기 시나리오 매핑
- [ ] 각 시나리오 스텝 ≥ 3, 액터·기대결과 명시
- [ ] 각 시나리오 검증 포인트 ≥ 2 (종료 + 중간)
- [ ] 각 시나리오 분기/예외 ≥ 1건
- [ ] 사전 데이터 셋업 명시
- [ ] 우선순위(P0~P2) 부여
- [ ] 모든 시나리오 trace-up
- [ ] 검증표 전 행 PASS

---

## 6. 사용자에게 질문할 시그널

- 자동화 도구 (Cypress / Playwright / Selenium / Postman)
- 테스트 환경 (DEV / STG / 별도 ITS 환경)
- 테스트 데이터 전략 (시드 / 매 회 초기화 / 누적)
- 외부 시스템 Stub 여부 (실 ERP 연동 / Mock 서버)
- 성능·부하 시나리오 포함 여부
- 보안 테스트 포함 여부 (인증/인가/SQL Injection 등)
- 사용자 계정 풀 (Role별 테스트 계정 준비)
- 시나리오 실행 빈도 (Smoke / Regression / Full)

---

## 7. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| 스텝이 1~2개로 끝남 | 최소 3단계, 시작 ~ 종료까지 |
| 분기/예외 시나리오 누락 | 정상 외에 반려·취소·타임아웃 등 ≥ 1 |
| 검증 포인트가 종료 시점 1개만 | 중간 체크포인트 ≥ 2 (DB / API / UI) |
| 데이터 셋업 모호 | 계정 ID / 마스터 데이터 / 잔여 상태 구체화 |
| FLW 분기와 ITS 시나리오 매핑 누락 | FLW-S## / B## ↔ ITS-### 대응 표 권장 |
| Trace-up이 FLW만 | 스텝에서 사용한 SCR·FUNC도 모두 포함 |
| 우선순위 누락 | P0(릴리즈 차단) / P1(중요) / P2(여유) |
| 단위 테스트 케이스를 ITS에 적음 | UTC로 이동 |
