## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 운영 대상 시스템 범위 / 운영 시간(24x7 / 업무시간).
- 운영자 역할(ROLE-##) 참조.
- 상위 REQ-N##·ARC trace-up 명시.

### §2 운영 대시보드 (REQ)
- 모니터링 지표 표: 지표명 / 임계치 / 측정 도구 / 알림 채널.
- 각 지표 카드 속성: `data-chunk="metric:{ID}"`
- 임계치는 정량 (예: CPU > 80% 5분 지속).

### §3 일상 운영 절차 (REQ)
- 일/주/월 단위 점검 체크리스트.
- 각 절차: ID / 주기 / 담당 / 단계 ≥ 3 / 정상 기준.
- 카드 속성: `data-chunk="procedure:{ID}"`

### §4 장애 대응 Runbook (REQ) — **가장 중요**
각 Runbook 카드 필수 요소:
- **증상** — 사용자가 보고하는 형태 + 모니터링 알림
- **영향 범위** — 영향 사용자·기능·SLA
- **확인 절차** — 단계 ≥ 3 (로그·메트릭·상태 점검)
- **복구 절차** — 단계 ≥ 3 + 검증 방법
- **에스컬레이션** — 임계 시간 / 보고 대상
- **사후 조치** — 회고 / RCA 작성 책임

카드 속성:
- `data-chunk="runbook:{ID}"`
- `data-trace-up="REQ-N##,ARC-CMP-##,..."`

### §5 백업/복구 (REQ)
- 백업 작업: 대상 / 주기 / 보존 / 저장 위치.
- 복구 절차: RPO / RTO 목표 + 단계.
- DR 시나리오 ≥ 1건 (전체 사이트 장애).

### §6 권한·접근 (REQ)
- 운영자 계정 관리 (생성·회수·MFA).
- SSH·DB·관리 콘솔 접근 경로.
- 감사 로그 위치·보존.

### §7 AI 메타데이터 (REQ)
- `primary_entities`에 핵심 시스템·메트릭 키워드.

### §8 검증표 (REQ, 자동)
- 모니터링 지표 ≥ 1 / 일상 절차 ≥ 1 / Runbook ≥ 1 / 백업 정책 / Trace 전건.

---

## 4. Trace 작성 원칙

- **상향 trace-up**:
  - Runbook → REQ-N## (가용성·복구), ARC-CMP-## (대상 컴포넌트)
  - 백업 작업 → REQ-N## (데이터 보존)
- 운영 절차에서 사용하는 기능은 FUNC-## 참조.
- 모든 ID에 프로젝트 prefix.

---

## 5. 자가 점검 체크리스트

- [ ] `<meta>` 모두 채움
- [ ] 운영 시간 / 운영자 역할 명시
- [ ] 모니터링 지표 ≥ 5건 + 임계치 정량화
- [ ] 일/주/월 점검 절차 각 ≥ 1건
- [ ] Runbook ≥ 3건 (서비스 다운 / DB 장애 / 외부 연동 실패 최소)
- [ ] 각 Runbook 증상·확인·복구·에스컬레이션·사후조치 5요소
- [ ] 백업 RPO/RTO 명시
- [ ] DR 시나리오 ≥ 1건
- [ ] 알림 채널 / 임계 시간(에스컬레이션) 명시
- [ ] 검증표 전 행 PASS

## 6. 사용자에게 질문할 시그널

- 운영 시간 (24x7 / 업무시간)
- 운영 인력 수 / On-call 체계
- 모니터링 도구 (Datadog / NewRelic / Grafana / Zabbix)
- 알림 채널 (Slack / Teams / PagerDuty / 문자)
- 에스컬레이션 경로 (L1 → L2 → L3)
- 백업 RPO / RTO 목표
- DR 사이트 보유 여부
- 감사 로그 보존 기간 / 규제 준수 (ISMS-P, SOX 등)
- 변경 관리 절차 (CAB / 자동 승인)

---

## 7. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| 임계치가 "비정상 시" | 정량 (CPU>80% 5분, 에러율>1%) |
| Runbook 복구 절차 1~2단계 | ≥ 3단계 + 검증 방법 |
| 에스컬레이션 임계 시간 누락 | "15분 내 미해결 시 L2" 명시 |
| 백업 보존 기간 미정 | 일/주/월/연 단위 정책 |
| DR 시나리오 누락 | 전체 사이트 장애 ≥ 1건 |
| 알림 채널 모호 | 채널명·수신자 그룹 명시 |
| 운영자 권한 회수 절차 누락 | 퇴사·이동 시 24시간 내 회수 |
| 사후 조치(RCA) 없음 | 5 Whys / 회고 책임자 명시 |
