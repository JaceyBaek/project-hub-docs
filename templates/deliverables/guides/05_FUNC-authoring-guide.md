## 2. ID 명명 규칙

- 기능: `{PROJECT}-FUNC-###` (3자리 zero-pad)
- 입출력 파라미터: `{PROJECT}-FUNC-###-I#` / `-O#`
- 예외/에러: `{PROJECT}-FUNC-###-E#`
- 외부 의존 (Integration Point): `{PROJECT}-FUNC-###-X#`

---

## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 기능 범주(예: 결재 / 조회 / 관리). 상위 REQ-F##, 상향 SCR/FLW, 하향 UTC 양방향 추적.

### §2 기능 목록 (REQ)
- 칼럼: ID / 기능명 / 분류 / 호출자(Caller) / 비고
- 누락된 기능이 본문에 등장하면 검증 FAIL.

### §3 기능 상세 (REQ) — **가장 중요**
각 기능 카드는 다음을 **모두** 포함:
- **기본 정보 표**: 목적 / API endpoint / HTTP method / 동기·비동기 / 트랜잭션 범위
- **입력 파라미터 표**: 이름 / 타입 / 필수 / 검증 규칙 / 기본값
- **출력/응답 표**: 이름 / 타입 / 설명 / 예시
- **비즈니스 로직** — 순서 있는 단계 ≥ 3 (가능하면 의사코드)
- **예외/에러** — 코드 / 메시지 / 처리 ≥ 1건
- **권한** — ROLE-## 참조
- **외부 의존** — DB 테이블 / 외부 API / 메시지 큐 (있는 경우)

카드 속성:
- `data-chunk="function:{ID}"`
- `data-trace-up="REQ-F##,SCR-###,FLW-###-S##,..."`
- `data-trace-down="UTC-###,..."`

### §4 데이터 모델 참조 (OPT)
- 기능이 다루는 엔티티 카탈로그. ERD 본문이 아니라 **참조 인덱스**.
- 정식 ERD는 별도 문서 또는 ARC §데이터.

### §5 AI 메타데이터 (REQ)
- `primary_entities` 에 핵심 도메인 객체 키워드.

### §6 검증표 (REQ, 자동)
- 기능 ≥ 1건 / 입출력 표 ≥ 1행 / 비즈니스 로직 ≥ 3단계 / 예외 ≥ 1건 / 권한 명시 / Trace 전건.

---

## 4. Trace 작성 원칙

- **양방향 필수**:
  - `data-trace-up` — REQ-F##, SCR-###, FLW-###-S## (호출 시작점)
  - `data-trace-down` — UTC-### (단위 테스트)
- ITS(통합테스트)는 FLW를 trace-up으로 두므로, FUNC가 ITS를 직접 trace-down으로 둘 필요는 없음.
- 모든 ID에 프로젝트 prefix.

---

## 5. 자가 점검 체크리스트

- [ ] `<meta>` 모두 채움
- [ ] 기능 목록(§2) ↔ 기능 상세(§3) 1:1 매칭
- [ ] 각 기능에 API endpoint + HTTP method 명시
- [ ] 각 기능 입출력 표 ≥ 1행, 검증 규칙 포함
- [ ] 각 기능 비즈니스 로직 ≥ 3단계
- [ ] 각 기능 예외 ≥ 1건 (성공만 적지 말 것)
- [ ] 각 기능 권한(ROLE-## 또는 PERM-##) 명시
- [ ] 외부 의존(DB/외부 API/큐) 명시
- [ ] 모든 기능 trace-up/down (특히 UTC 매핑)
- [ ] 동기/비동기 명시
- [ ] 검증표 전 행 PASS

## 6. 사용자에게 질문할 시그널

- 시스템명 / 프로젝트 코드
- API 스타일 (REST / gRPC / GraphQL / RPC)
- 인증 방식 (JWT / Session / OAuth)
- 트랜잭션 경계 정책 (Service 단위 / Saga / 최종일관성)
- 외부 시스템 (ERP, 메시지 큐, 인증 IdP)
- 비동기 처리 필요 여부 (배치, 큐 작업)
- 에러 코드 체계 (HTTP 상태 + 도메인 코드)
- 다국어 응답 메시지

## 7. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| API endpoint 누락 | `METHOD /resource/{id}` 명시 |
| 입력 검증 규칙 모호 ("필요 시") | 구체 조건 (예: "≥1, ≤100", "이메일 형식") |
| 예외/에러 누락 | 최소 1건 (404/403/422/500 등 도메인 매핑) |
| 비즈니스 로직 1~2단계 | 최소 3단계, 분기·트랜잭션 명시 |
| 권한 정보를 ROLE에만 두고 누락 | FUNC 카드에 ROLE-## 명시 (양쪽 표기) |
| 외부 의존 누락 | DB 테이블·외부 API·큐 모두 나열 |
| UTC 매핑 누락 | 모든 FUNC에 1개 이상 UTC trace-down |
| 동기/비동기 미표기 | 비동기 시 큐/콜백/폴링 방식 명시 |
