# 화면정의서 (SCR) — AI 작성 가이드

> **이 문서의 독자는 AI 에이전트입니다.** 화면 사용자에게 노출되지 않습니다.
> 템플릿(`docs/02_design/03_SCR_화면정의서.html`)을 복사해 실제 화면을 채울 때 반드시 이 가이드를 먼저 로드하십시오.

---

## 0. 작성 절차

1. 템플릿 복사 → `projects/<프로젝트>/docs/02_design/03_SCR_<프로젝트명>_화면정의서_<YYYYMMDD>.html`
2. `<meta>` 단일 소스 갱신 (project-id / doc-id / owner / tags / hints / primary-entities)
3. `<title>` — `SCR · {시스템명} 화면정의서`
4. **화면 목록(§2)** — 전체 카탈로그. ID·화면명·플랫폼(Web/Mobile/Tablet) 명시
5. **화면 상세(§3)** — 카드 단위로 1 화면 = 1 청크
6. **공통 컴포넌트(§4)** — 재사용 컴포넌트 정의
7. **AI 메타데이터(§5)** 갱신
8. **검증표(§6)** 자동 계산, 모든 행 PASS

|---|---|
| `REQ` | 필수 |
| `OPT` | 선택 |
| `COND` | 조건부 (예: 반려 시 의견 필수) |

## 2. ID 명명 규칙

- 화면: `{PROJECT}-SCR-###` (3자리 zero-pad)
- 화면 내 액션: `{PROJECT}-SCR-###-A#` (A = Action)
- 화면 내 섹션 분할 청크: `screen:SCR-###:section` (대형 화면용)
- 플랫폼별 화면이 분리되면 별도 ID — 예: 데스크톱(SCR-003) ↔ 모바일(SCR-010)

---

## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 화면 ID 체계 + 상위 REQ-F##, 하향 FUNC-### 양방향 추적 명시.

### §2 화면 목록 (REQ)
- 전체 화면 카탈로그. 칼럼: ID / 화면명 / 설명 / 플랫폼.
- 누락된 화면이 본문에 등장하면 검증 FAIL.

### §3 화면 상세 (REQ) — **가장 중요**
각 화면 카드는 다음을 **모두** 포함:
- **기본 정보 표**: 목적 / 진입 경로 / 권한 / 레이아웃
- **필드 표**: 필드명 / 타입 / 필수(Y/N/COND) / 검증·비고
- **액션 목록** ≥ 1건. 각 액션에 API endpoint 또는 동작 명세
- **상태 / 빈상태 / 에러** — 로딩·빈상태·인라인 에러 3가지 정의

카드 속성:
- `data-chunk="screen:{ID}"`
- `data-trace-up="REQ-F##,..."`
- `data-trace-down="FUNC-###,..."`

### §4 공통 컴포넌트 (OPT)
- 2개 이상 화면에서 재사용되는 컴포넌트만.
- 컴포넌트마다 동작 요약 1문장.

### §5 AI 메타데이터 (REQ)
- `<meta>` 와 일치. `primary_entities`는 화면 그룹 키워드.

### §6 검증표 (REQ, 자동)
- 화면 ≥ 1건 / 필드 표 ≥ 1행 / 액션 ≥ 1건 / Trace 전건.

---

## 4. Trace 작성 원칙

- **양방향 필수**:
  - `data-trace-up` — 상위 REQ-F## (콤마구분)
  - `data-trace-down` — 하향 FUNC-### (콤마구분)
- FLW 에서 참조하는 화면은 자동으로 역추적되지만, SCR 카드에도 `data-trace-up`에 FLW-### 추가 권장.
- 모든 ID에 프로젝트 prefix.

---

## 5. 자가 점검 체크리스트

- [ ] `<meta>` 모두 채움
- [ ] 화면 목록(§2) ↔ 화면 상세(§3) 1:1 매칭
- [ ] 각 화면 기본정보 표 (목적/진입/권한/레이아웃) 채움
- [ ] 각 화면 필드 표 ≥ 1행, 검증 규칙 명시
- [ ] 각 화면 액션 ≥ 1건, API endpoint 또는 동작 명세
- [ ] 각 화면 상태/빈상태/에러 정의
- [ ] 모든 화면 trace-up/down
- [ ] 모바일 화면은 데스크톱 화면과 별도 ID
- [ ] 검증표 전 행 PASS

---

## 6. 사용자에게 질문할 시그널

- 시스템명 / 프로젝트 코드
- 대상 플랫폼 (Web only? Mobile 포함? Tablet?)
- 디자인 시스템 / UI 라이브러리 (TipTap, MUI 등)
- 권한 체계 (ROLE 문서가 있는지)
- 화면 단위 SLA (로딩 시간, 폴링 주기 등)
- 다국어 대상 여부
- 접근성 요구 수준 (WCAG AA/AAA)

---

## 7. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| 필드 검증을 "필요 시 검증" 같이 모호하게 | 구체적 조건 (예: "공백 불가", "≤20MB") |
| 액션에 API endpoint 누락 | 모든 액션에 `METHOD /path` 또는 동작 명세 |
| 모바일 변형을 같은 SCR-### 안에 섞음 | 별도 ID로 분리 (SCR-003 ↔ SCR-010) |
| `data-trace-down`에 FUNC 누락 | 상신·승인 등 백엔드 동작은 모두 FUNC 매핑 |
| 빈상태/에러 정의 누락 | 모든 화면에 3-상태(로딩/빈/에러) 필수 |
| 공통 컴포넌트를 각 화면마다 중복 정의 | §4로 추출 |
