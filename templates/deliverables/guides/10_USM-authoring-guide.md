> 템플릿(`docs/05_deploy/10_USM_사용자매뉴얼.html`)을 복사해 실제 사용 가이드를 채울 때 반드시 이 가이드를 먼저 로드하십시오.

---

## 0. 작성 절차

1. 템플릿 복사 → `projects/<프로젝트>/docs/05_deploy/10_USM_<프로젝트명>_사용자매뉴얼_<YYYYMMDD>.html`
2. `<meta>` 단일 소스 갱신 (project-id / doc-id / owner / tags / primary-entities)
3. `<title>` — `USM · {시스템명} 사용자매뉴얼`
4. **§2 시작하기** — 로그인·기본 화면 안내
5. **§3 주요 작업(Task)** — 1 작업 = 1 청크
6. **§4 FAQ** — 자주 묻는 질문
7. **§5 용어집(Glossary)** — 비즈니스 용어 정의
8. **AI 메타데이터(§6)** 갱신
9. **검증표(§7)** 자동 계산

## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 대상 사용자(Role 기준) / 접근 경로 / 지원 채널.
- 상위 SCR-### 양방향 추적 명시 (각 작업이 어느 화면 기반인지).

### §2 시작하기 (REQ)
- 로그인 절차 / 기본 화면 안내 / 메뉴 구조.
- 첫 사용자 기준으로 작성 (사전 지식 0 가정).

### §3 주요 작업 (REQ) — **가장 중요**
각 작업 카드 필수 요소:
- **목적** — 1문장 (사용자 관점)
- **사전 조건** — 필요 권한·데이터 (있는 경우)
- **수행 단계** — 순서 있는 ≥ 3단계, 각 단계에 화면 캡처 또는 화면 ID
- **결과 확인** — 성공 시 어떻게 보이는지
- **자주 발생하는 오류** — 메시지 + 대응 ≥ 1건

카드 속성:
- `data-chunk="task:{ID}"`
- `data-trace-up="SCR-###,ROLE-##,..."`

**문체 원칙**:
- 사용자에게 직접 말하듯 ("…를 클릭합니다").
- 전문 용어는 §5 용어집 참조 링크.
- 한 단계 = 한 동작 (여러 동작 묶지 말 것).

### §4 FAQ (REQ, ≥ 5건)
- Q/A 쌍. A는 ≤ 3문장 + 관련 작업/화면 링크.
- 검색 키워드 데이터 속성: `data-keywords="..."` (선택)
- 카드 속성: `data-chunk="faq:{ID}"`

### §5 용어집 (OPT, 권장)
- 비즈니스 용어 / 시스템 용어.
- 정의 + 동의어(synonym) + 관련 화면.
- 카드 속성: `data-chunk="glossary:{ID}"`

### §6 AI 메타데이터 (REQ)
- `primary_entities`에 핵심 작업·도메인 용어.
- `synonyms` 메타 필수 (사용자가 다양한 표현으로 검색하므로).

### §7 검증표 (REQ, 자동)
- 시작하기 ≥ 1 / 작업 ≥ 3 / FAQ ≥ 5 / 모든 작업에 결과 확인 + 오류 대응 / Trace 전건.

---

## 4. Trace 작성 원칙

- **상향 trace-up**:
  - Task → SCR-### (수행 화면), ROLE-## (필요 권한)
  - FAQ → 관련 Task 또는 SCR
- USM은 SCR/ROLE을 가장 많이 참조하는 산출물.
- 모든 ID에 프로젝트 prefix.

---

## 5. 자가 점검 체크리스트

- [ ] `<meta>` 모두 채움 (synonyms 포함)
- [ ] 대상 사용자(Role) 명시
- [ ] 시작하기 섹션 (로그인 + 화면 안내)
- [ ] 주요 작업 ≥ 3건
- [ ] 각 작업 단계 ≥ 3, 화면 캡처 또는 SCR-### 참조
- [ ] 각 작업 결과 확인 + 오류 대응 명시
- [ ] FAQ ≥ 5건
- [ ] 전문 용어 ≥ 1건 용어집 정의
- [ ] 모든 작업 trace-up
- [ ] 사용자 시점 문체 (개발자 용어 X)
- [ ] 검증표 전 행 PASS

---

## 6. 사용자에게 질문할 시그널

- 사용자 페르소나 / Role 종류
- 접근 채널 (웹 / 모바일 / 양쪽)
- 지원 채널 (헬프데스크 / 채팅봇 / 매뉴얼만)
- 화면 캡처 보유 여부 (없으면 SCR ID 참조)
- 영상 가이드 포함 여부
- 다국어 대상
- 인쇄용 PDF 출력 필요 여부
- 접근성 (WCAG 준수 / 스크린리더)
- 신규 가입 절차 안내 필요 여부

---

## 7. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| 개발자 용어 사용 ("API 호출") | 사용자 행위 ("저장 버튼 클릭") |
| 단계 하나에 동작 여러 개 묶음 | 1 단계 = 1 동작 |
| 화면 캡처/SCR 참조 없음 | 각 단계에 시각 자료 또는 SCR-### |
| 결과 확인 누락 | 성공 시 어떻게 보이는지 명시 |
| 오류 대응 누락 | 자주 발생 오류 + 메시지 + 대응 ≥ 1 |
| FAQ가 일반론 ("문제가 있으면 문의") | 구체 케이스 + 절차·연락처 |
| 용어 정의 누락으로 마찬가지 단어 반복 | 용어집 §5 활용 |
| synonyms 메타 누락 | 검색 효율 위해 동의어 등록 필수 |
