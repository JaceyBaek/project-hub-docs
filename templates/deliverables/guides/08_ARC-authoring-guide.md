> **이 문서의 독자는 AI 에이전트입니다.** 화면 사용자에게 노출되지 않습니다.
> 템플릿(`docs/08_ARC_아키텍처.html`)을 복사해 실제 아키텍처를 채울 때 반드시 이 가이드를 먼저 로드하십시오.

---

## 0. 작성 절차

1. 템플릿 복사 → `projects/<프로젝트>/docs/08_ARC_<프로젝트명>_아키텍처.html`
2. `<meta>` 단일 소스 갱신 (project-id / doc-id / owner / tags / primary-entities)
3. `<title>` — `ARC · {시스템명} 아키텍처`
4. **§2 논리 아키텍처** — 컴포넌트·계층·책임
5. **§3 배포 아키텍처** — 환경·노드·네트워크
6. **§4 데이터 아키텍처** — 주요 엔티티·저장소
7. **§5 보안/비기능** — 인증·인가·암호화·SLA
8. **§6 결정 기록(ADR)** — 주요 의사결정
9. **AI 메타데이터(§7)** 갱신
10. **검증표(§8)** 자동 계산

---

## 2. ID 명명 규칙

- 컴포넌트: `{PROJECT}-ARC-CMP-##` (Application / Service / Worker / etc)
- 노드: `{PROJECT}-ARC-NODE-##` (배포 단위)
- 데이터 저장소: `{PROJECT}-ARC-STORE-##` (DB / 캐시 / 큐 / 파일스토어)
- 외부 시스템: `{PROJECT}-ARC-EXT-##`
- 의사결정: `{PROJECT}-ADR-###`

---

## 3. 섹션별 작성 규칙

### §1 개요 (REQ)
- 시스템 목적 / 핵심 NFR (가용성·성능·보안 목표치).
- 4+1 뷰 / C4 / Arc42 중 무엇을 기반으로 했는지.
- 상위 REQ-N## (비기능요구사항) trace-up 명시.

### §2 논리 아키텍처 (REQ)
- 컴포넌트 카탈로그 (ID / 이름 / 책임 / 기술스택 / 의존).
- 컴포넌트 간 호출 다이어그램 (또는 표 대체).
- 각 컴포넌트 카드 속성: `data-chunk="component:{ID}"`

### §3 배포 아키텍처 (REQ)
- 환경 목록 (DEV/STG/PROD) + 노드 매핑.
- 네트워크 경계 / 방화벽 / VPC / DMZ.
- 컨테이너 오케스트레이션(K8s/ECS/Nomad)·서버리스 여부.

### §4 데이터 아키텍처 (REQ)
- 주요 엔티티 (또는 ERD 링크).
- 저장소 매트릭스 (RDBMS / NoSQL / 캐시 / 큐 / 파일).
- 데이터 보존·백업·복구 정책.

### §5 보안 / 비기능 (REQ)
- 인증·인가 (IdP·토큰·세션).
- 암호화 (전송·저장).
- 비기능 목표: 가용성(SLA), 성능(P95), 확장성, 모니터링·로깅.

### §6 결정 기록 ADR (OPT, 강력 권장)
- 1 ADR = 1 결정. 형식: 상황 / 결정 / 대안 / 결과.
- 각 카드 속성: `data-chunk="adr:{ID}"`

### §7 AI 메타데이터 (REQ)
- `primary_entities`에 핵심 컴포넌트·기술명.

### §8 검증표 (REQ, 자동)
- 컴포넌트 ≥ 1 / 배포 환경 ≥ 1 / 저장소 ≥ 1 / 보안 항목 ≥ 1 / Trace-up 전건.

---

## 4. Trace 작성 원칙

- **상향 의무**:
  - `data-trace-up` — REQ-N## (해당 NFR), REQ-F## (기능적 근거)
  - `data-trace-down` — 일반적으로 없음 (FUNC가 ARC를 참조하지만 ARC는 종착점)
- 컴포넌트 카드는 자기 안에서 사용하는 외부 시스템(EXT-##)·저장소(STORE-##)에 cross-reference.
- 모든 ID에 프로젝트 prefix.

---

## 5. 자가 점검 체크리스트

- [ ] `<meta>` 모두 채움
- [ ] 컴포넌트 카탈로그 ≥ 1, 책임·기술스택·의존 명시
- [ ] 배포 환경 ≥ 1 (PROD 필수), 노드 매핑
- [ ] 데이터 저장소 ≥ 1, 백업·보존 정책
- [ ] 인증·인가·암호화 명시
- [ ] NFR 목표치 정량화 (SLA %, P95 ms 등)
- [ ] 모든 REQ-N##(비기능 요구사항)에 매핑된 ARC 항목 존재
- [ ] ADR ≥ 1건 (핵심 결정)
- [ ] 검증표 전 행 PASS

---

## 6. 사용자에게 질문할 시그널

- 호스팅 환경 (On-prem / AWS / Azure / GCP / Hybrid)
- 컨테이너 오케스트레이션 (K8s / ECS / 없음)
- DB 엔진 (PostgreSQL / Oracle / MSSQL / MySQL)
- 메시지 큐 / 이벤트 버스 사용 여부
- 인증 IdP (Cognito / Keycloak / Azure AD / 내부 LDAP)
- 가용성 목표 SLA (예: 99.9%, 99.95%)
- 성능 목표 (TPS, P95 응답시간)
- 데이터 보존 정책 (기간 / 백업 주기 / DR)
- 모니터링 스택 (Datadog / NewRelic / ELK / Prometheus)
- 외부 연동 시스템 (ERP, CRM, 결제 등)

---

## 7. 흔한 실수

| 실수 | 올바른 처리 |
|---|---|
| NFR 목표가 "충분히 빠르게" | 정량 (P95 ≤ 200ms, 99.9% 가용성) |
| 컴포넌트 책임 모호 | 1문장 책임 (Single Responsibility) |
| 환경 매트릭스에 PROD만 | DEV/STG/PROD 최소 3환경 |
| ADR 누락 | 핵심 결정(언어·DB·인증) ≥ 1건 |
| REQ-N## 미매핑 | 모든 비기능 요구사항이 ARC에 반영되어야 함 |
| 보안 섹션이 "인증 적용" 한 줄 | 인증 / 인가 / 암호화 / 감사로깅 4개 모두 |
| 데이터 보존 정책 누락 | 보존 기간 / 백업 / 복구 RPO/RTO |
| 외부 시스템 누락 | EXT-## 로 별도 정의, 의존 명시 |
