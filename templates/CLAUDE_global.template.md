## 개발 환경

- **언어:** Python
- **저장소 구조:** 프로젝트별 독립 repo 또는 project-hub repo 내 관리 (프로젝트별 결정)
- **브랜치 전략:** Git Flow
  - `main` — 안정 버전
  - `develop` — 개발 통합 브랜치
  - `feature/기능명` — 기능 개발 (develop에서 분기 → develop으로 병합)
  - `fix/버그명` — 버그 수정 (develop에서 분기 → develop으로 병합)
- **CI/CD:** GitHub Actions (린트: flake8 / 테스트: pytest)
- **네이밍 규칙:**
  - 프로젝트 폴더·Python 파일: 영문 소문자 + 언더바 (`atlassian_integration`)
  - 브랜치: 영문 소문자 + 하이픈 (`feature/jira-issue-sync`)
  - 클래스: PascalCase / 함수·변수: snake_case
- **배포 방식:** 로컬 PC에서 Python 가상환경(venv)으로 직접 실행 — 사내 서버 배포는 추후 검토
- **소스 주석 규칙:** 모든 소스 코드 작성 시 충분한 주석 필수 — 함수·클래스 목적, 파라미터, 주요 로직, 외부 의존성 등 명시
- **스케줄러 방침:** 일배치 등 스케줄러 구현 시 **APScheduler** 사용 — Windows 작업 스케줄러 사용 금지 (향후 Docker 전환 시 OS 무관하게 동작)
- **경로 관리 방침:** 파일 경로는 하드코딩 금지, 반드시 환경변수로 관리
- **공통 모듈:** `projects/shared/` — 프로젝트 간 공유 유틸 모듈
  - `confluence_client.py` — Confluence Data Center REST API 공통 클라이언트
  - 사용 시 `sys.path.insert(0, os.path.join(os.path.dirname(__file__), '..', '..', 'shared'))` 로 경로 추가
  - 환경 변수: `CONFLUENCE_URL` / `CONFLUENCE_USERNAME` / `CONFLUENCE_API_TOKEN`

## 프로젝트 내부 규칙

각 프로젝트 진입 시 해당 프로젝트의 `CLAUDE.md`를 우선 참조.

### 산출물 작성

- **형식:** HTML 기반 (`.html`)
- **명명규칙:** `{프로젝트명}_{산출물명}_{YYYYMMDD}.html`
  - 날짜: `datetime.now().strftime("%Y%m%d")` 사용 (하드코딩 금지)
  - 동일 날짜 수정: `_v1`, `_v2` suffix / 날짜 바뀌면 버전 리셋
  - 구버전: `archive/`로 이동
- **템플릿 위치:** project-hub `templates/deliverables/` 참조
- **Confluence 게시:** `templates/deliverables/DEPLOYMENT.md` §4 참조
  - 산출물 페이지: `423870940` 하위
  - 위키 게시 시 최신 버전만 유지

### 프로젝트 히스토리

- 위치: `_manage/history/YYYYMM_history.md` (월 단위, 날짜별 append)
- "오늘 작업 정리해줘" 트리거 시 자동 기록

### 프로젝트 To-Do

- 위치: `_manage/todo.md`
- 컬럼: `ID / 제목 / 우선순위 / 상태 / 기한 / 완료일`
- 우선순위: 높음·보통·낮음 / 상태: 대기·진행중·완료·보류

### 프로젝트 이슈

- 위치: `_manage/issues.md`
- 컬럼: `ID / 유형 / 제목 / 내용 / 상태 / 등록일 / 완료일`
- 유형: 버그·변경요청·리스크 / 상태: 오픈·진행중·완료·보류

### 회의록

- 위치: `_manage/meetings/YYYYMMDD_meeting_회의제목.md`
- 항목: 일시 / 참석자 / 안건 / 논의 내용 / 결정사항 / 액션 아이템(담당자·기한)

### 의사결정 로그

- 위치: `_manage/decisions.md`
- 항목: ID / 일자 / 결정 내용 / 결정 배경 및 근거 / 결정자 / 관련 이슈·회의록

## 응답 규칙

1. **한국어로만 응답** — 모든 답변은 한국어로 작성
2. **불필요한 서두 금지** — 칭찬, 안녕 등 없이 바로 본론
3. **사실 및 데이터 기반 답변만** — 추측 불가, 제안은 가능하되 반드시 "제안" 또는 "검토 필요"로 명시
4. **할루시네이션 방지 우선** — 모르면 모른다고 명시
5. **번호 목록** — 수정 사항이 여러 개일 경우 번호를 매겨 정리
6. **코드 및 산출물 우선** — 설명보다 즉시 적용 가능한 코드, 문서 초안, 템플릿을 먼저 제공
7. **확인 질문은 1개만** — 모호한 요청은 가정 명시 후 진행, 끝에 확인 질문 하나
8. **Step-by-step 진행**
   - 작업 시작 전 전체 진행 순서를 간략히 나열
   - 한 단계씩 실행 후 {{USER_NAME}} 확인 → 다음 단계로 이동
   - 명확한 작업은 바로 실행, 불확실한 경우만 확인 질문 1개
   - 서브에이전트(Agent 툴) 사용은 {{USER_NAME}}가 명시적으로 요청한 경우에만
9. **실수 반복 금지** — 이전에 지적받은 코드/방식은 재사용 금지
